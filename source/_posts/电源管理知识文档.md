## ACPI

ACPI（Advanced Configuration and Power Interface，高级配置与电源接口）是一套开放行业标准，用于统一操作系统对硬件配置、电源和温度的管理。它不仅负责睡眠与唤醒，也参与设备发现、资源分配和事件处理。

它的前身是APM（Advanced Power Management，高级电源管理），早期由 BIOS 主导的电源管理方案，操作系统对硬件和负载的掌控有限。

### 主要能力

- **系统电源管理**：控制系统进入工作、睡眠、休眠或关机状态。
- **硬件发现与配置**：向操作系统描述主板及外设，协助完成设备枚举和资源分配。
- **设备电源管理**：配合驱动程序调整网卡、显卡、USB 控制器和存储设备的供电状态。
- **处理器电源管理**：支持空闲节能、性能调节和温度控制。
- **热管理**：读取温度信息，配合风扇控制和高温降频。
- **事件处理**：响应电源键、合盖、电池告警、热插拔和唤醒信号。
- **电池管理**：提供电量、充放电状态及相关告警信息。

### 关键组件

| 组件 | 作用 |
| --- | --- |
| ACPI 表 | 固件向操作系统提供的硬件描述和配置数据 |
| DSDT | 描述系统主要设备及其控制方法 |
| SSDT | 对 DSDT 进行补充，常用于处理器或平台相关功能 |
| FADT | 提供固定硬件寄存器和电源管理相关参数 |
| AML | ACPI 控制方法使用的字节码，由操作系统中的解释器执行 |
| ACPI Namespace | 由设备对象和控制方法构成的树形命名空间 |
| SCI | ACPI 用于向操作系统报告事件的系统控制中断 |

固件提供 ACPI 表和 AML 控制方法，操作系统解析这些信息并建立设备模型。进入睡眠、恢复设备或处理唤醒事件时，操作系统会调用相应的控制方法。

固件描述错误、AML 实现缺陷或驱动程序配合异常，都可能导致无法睡眠、唤醒黑屏、风扇异常或电池识别失败。因此，这类故障不能简单归因于操作系统，也不能一概认定为 ACPI 表问题。

## OSPM

OSPM（Operating System-directed configuration and Power Management，操作系统主导的配置与电源管理）是操作系统内部的配置与电源管理模型。它根据用户设置、系统负载、设备能力和唤醒需求，决定何时切换电源状态，并协调固件与驱动程序完成切换。

其主要职责包括：

- 解析 ACPI 表，执行 AML 控制方法。
- 枚举和配置硬件设备。
- 管理 S0 至 S5 等系统电源状态。
- 管理设备电源状态和处理器节能状态。
- 根据唤醒需求配置键盘、网卡和电源键等唤醒源。
- 处理温度、电池、电源键和合盖等事件。
- 向用户态提供睡眠、休眠和电源策略接口。

在 Linux 中，ACPI 相关内核子系统、驱动模型和电源管理框架共同承担这些工作，用户态的 acpid 等程序可辅助处理事件。在 Windows 中，内核电源管理器及相关驱动框架承担类似职责。

## 全局状态与系统电源状态

### 全局状态

| 全局状态 | 对应系统状态 | 含义 |
| --- | --- | --- |
| G0 | S0 | 系统正常工作 |
| G1 | S1、S2、S3、S4 | 系统处于某种睡眠或休眠状态 |
| G2 | S5 | 软关机，仍保留部分待机供电 |
| G3 | 无对应 S 状态 | 机械断电，外部电源和电池供电被切断 |

G3 与 S5 的区别在于是否仍存在待机供电。S5 下可以响应电源键等信号，G3 下硬件基本完全断电，ACPI 不再参与管理。

### 系统电源状态

| 状态 | 常见名称 | 上下文保存位置 | 掉电后能否恢复会话 | 恢复速度 | 典型功耗 |
| --- | --- | --- | --- | --- | --- |
| S0 | 工作状态 | 实时保存在内存和处理器中 | 不能 | 无需恢复 | 取决于负载 |
| S1 | 浅睡眠 | 内存及处理器硬件上下文 | 不能 | 极快 | 较高 |
| S2 | 较浅睡眠 | 主要保存在内存中 | 不能 | 快 | 中等 |
| S3 | 挂起到内存 | 内存 | 不能 | 很快 | 低 |
| S4 | 挂起到磁盘 | 非易失性存储 | 可以 | 较慢 | 极低 |
| S5 | 软关机 | 不保存 | 不保存会话 | 完整冷启动 | 极低 |

表中的功耗和速度是相对概念，实际表现取决于硬件平台、固件、驱动和外设供电设计。

#### S0：工作状态

S0 是系统正常执行程序的状态。处理器可以运行指令，内存可以正常读写，操作系统也可以分别调整处理器和各个设备的功耗。

S0 并不意味着整机始终以最高功耗运行。处理器调频、处理器空闲节能和设备运行时电源管理，都发生在 S0 内。

#### S0：低功耗待机

部分现代平台使用 S0 Low Power Idle 实现待机，Windows 的现代待机属于这一模式。系统没有进入传统 S3，而是在 S0 内尽可能关闭或降低处理器与设备的功耗。

屏幕熄灭后，系统仍可能按策略短暂活动，处理网络连接、通知或后台任务。因此，它通常具有较快恢复和保持连接的优势，也可能带来较高的待机耗电、异常发热或驱动兼容问题。

并非所有标称低功耗待机的平台都提供相同的联网能力，具体行为取决于操作系统策略、硬件设计和应用支持。

#### S1 与 S2：早期浅睡眠

S1 会停止处理器执行指令，但保留处理器、缓存和芯片组的大部分硬件上下文，内存继续保持刷新。它的恢复速度很快，但节能效果有限。

S2 会进一步关闭处理器和总线时钟，处理器及缓存上下文可能丢失，唤醒时需要重新初始化处理器。内存仍需保持供电。

S1 和 S2 都依赖持续供电，掉电会丢失当前会话。由于节能收益有限，而 S3 和 S0 低功耗待机能满足大多数平台需求，这两种状态在现代消费级计算机上已很少见。

#### S3：挂起到内存

S3 也称 STR，是传统睡眠的常见实现。进入 S3 前，操作系统保存必要的软件和硬件上下文，随后关闭处理器及大部分设备，只保留内存刷新、实时时钟和唤醒电路等必要供电。

由于运行现场保留在内存中，唤醒后可以直接恢复之前的程序、窗口和文档，通常只需较短时间。

S3 的主要限制是依赖内存供电。如果待机期间电池耗尽或供电中断，内存内容就会丢失，未保存的工作也会随之丢失。

##### 进入 S3 睡眠的典型流程

1. 用户或系统策略发起睡眠请求。
2. OSPM 检查设备和驱动是否支持挂起，并确认唤醒需求。
3. 系统暂停用户任务和相关设备活动，驱动保存必要的设备上下文。
4. 操作系统配置唤醒源，并调用 ACPI 控制方法通知固件准备进入目标状态。
5. 处理器上下文被保存，芯片组关闭处理器及大部分设备供电，保留内存和唤醒电路。
6. 唤醒信号到达后，硬件恢复供电，操作系统重新初始化设备并恢复之前的运行现场。

#### S4：挂起到磁盘

S4 通常称为休眠。操作系统把内存镜像写入非易失性存储，然后关闭系统的大部分供电。Windows 通常使用 hiberfil.sys 保存镜像，Linux 则通常使用交换分区或交换文件。

恢复时，系统需要经过固件初始化和镜像读取，再恢复之前的运行现场。它通常比 S3 慢，但休眠期间即使完全断电，镜像仍然保留。

S4 需要足够的存储空间，并会产生镜像写入和读取开销。实际镜像大小和压缩方式由操作系统决定，不一定始终与物理内存容量完全相同。

#### S5：软关机

S5 是操作系统完成关机流程后的状态。系统不保存运行上下文，内存内容被丢弃，再次开机需要完整启动固件、内核和用户会话。

S4 与 S5 在外观上可能很相似，二者都可以表现为屏幕熄灭和风扇停转。关键区别在于 S4 存在可恢复的休眠镜像，而 S5 没有。

## 电源状态的层次

| 类型 | 管理对象 | 说明 |
| --- | --- | --- |
| G 状态 | 整机全局状态 | 描述工作、睡眠、软关机和机械断电 |
| S 状态 | 系统睡眠与关机状态 | 描述操作系统和整机上下文的保存及恢复方式 |
| C 状态 | 处理器空闲状态 | 处理器无任务执行时降低功耗，系统仍处于 S0 |
| P 状态 | 处理器性能状态 | 处理器运行时调整频率和电压，系统仍处于 S0 |
| D 状态 | 单个设备状态 | 控制某个设备的工作功耗和供电水平 |

例如，一台处于 S0 的计算机可以让空闲处理器进入较深的 C 状态，同时让暂时不用的设备进入 D3。系统仍在运行，并没有进入传统意义上的睡眠。

### C 状态

C 状态用于处理器空闲节能。C0 表示处理器正在执行指令，更深的空闲状态会逐步关闭部分时钟或功能单元，以减少功耗。

进入越深的状态，通常节能效果越明显，但退出延迟也可能增加。具体状态名称和能力由处理器及平台定义，不能仅凭编号跨平台比较。

### P 状态

P 状态用于处理器运行时的性能与功耗调节。操作系统可以根据负载请求不同的性能水平，实际频率和电压还可能受到硬件策略、温度和功耗限制影响。

C 状态解决处理器空闲时如何省电，P 状态解决处理器工作时以何种性能运行。

### D 状态

D 状态描述单个设备的电源水平。D0 表示设备正常工作，D1 和 D2 是可选的中间节能状态，D3 表示最低功耗状态。

设备是否支持中间状态，以及 D3 下是否仍保留部分供电，取决于设备本身和平台设计。设备进入低功耗状态后，驱动程序必须能够正确恢复其上下文，否则可能出现唤醒后设备失效。

## 操作系统中的对应关系

| 操作或现象 | 常见实现 |
| --- | --- |
| Windows 现代待机 | S0 低功耗待机 |
| Linux s2idle | S0 内的低功耗空闲挂起 |
| Linux deep | 通常对应 S3 |
| Linux suspend | 可能使用 s2idle 或 deep，取决于平台配置 |
| Linux hibernate | 通常对应 S4 |
| Windows 休眠 | 通常对应 S4 |
| Windows 快速启动 | 使用休眠机制保存内核状态 |
| 普通关机 | 通常进入 S5 |

Linux 中的 freeze、mem 和 disk 是内核提供的挂起方式名称，不能在所有场景下与 ACPI 状态机械地一一对应。尤其是 mem 模式，仍需进一步确认当前使用的是 s2idle 还是 deep。

### 混合睡眠

混合睡眠常见于 Windows 桌面平台。系统进入 S3 的同时保存休眠镜像，平时可以从内存快速唤醒；如果睡眠期间掉电，则可以使用磁盘镜像恢复。

它结合了 S3 的快速恢复与 S4 的掉电保护，但会增加磁盘写入和存储空间占用。

### 快速启动

Windows 快速启动利用休眠机制保存内核和驱动状态。关机前用户会话会被注销，下次开机时恢复内核状态，而不是恢复用户之前打开的程序。

## 判断与排查方法

Windows：

```powershell
# 系统可用或不可用的睡眠状态
powercfg /a
```

Linux：

```bash
# 内核支持的挂起方式
cat /sys/power/state
# mem 模式可选路径及当前选择
cat /sys/power/mem_sleep
```
